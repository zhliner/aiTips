# 技能设计的说服原则

## 概述

LLM 对人类适用的说服原则同样有响应。理解这种心理学有助于你设计更有效的技能 —— 不是为了操纵，而是为了确保关键实践即使在压力下也能被遵循。

**研究基础：** Meincke 等人（2025）在 N=28,000 次 AI 对话中测试了 7 种说服原则。说服技术使合规率提高了一倍以上（33% → 72%，p < .001）。

## 七大原则

### 1. Authority（权威）
**含义：** 对专业知识、凭证或官方来源的遵从。

**在技能中的运作方式：**
- 祈使性语言："YOU MUST""Never""Always"
- 无商量余地的框架："No exceptions"
- 消除决策疲劳和找借口行为

**使用时机：**
- 纪律执行类技能（TDD、验证要求）
- 安全关键实践
- 成熟的最佳实践

**示例：**
```markdown
✅ 在测试之前就写了代码？删除它。重新开始。没有例外。
❌ 如果可行的话，考虑先写测试。
```

### 2. Commitment（承诺）
**含义：** 与先前行动、声明或公开表态保持一致。

**在技能中的运作方式：**
- 要求宣告："宣告技能使用"
- 强制明确选择："选择 A、B 或 C"
- 使用跟踪：清单的 todo

**使用时机：**
- 确保技能确实被遵循
- 多步骤流程
- 问责机制

**示例：**
```markdown
✅ 当你找到一个技能时，你必须宣告："我正在使用 [技能名称]"
❌ 考虑让你的伙伴知道你在使用哪个技能。
```

### 3. Scarcity（稀缺性）
**含义：** 时间限制或有限可用性带来的紧迫感。

**在技能中的运作方式：**
- 时间限定的要求："在继续之前"
- 顺序依赖："紧接在 X 之后"
- 防止拖延

**使用时机：**
- 立即验证要求
- 时间敏感的工作流
- 防止"我稍后再做"

**示例：**
```markdown
✅ 完成任务后，立即在继续之前请求代码审查。
❌ 你可以在方便的时候审查代码。
```

### 4. Social Proof（社会认同）
**含义：** 遵从他人所做的事情或被认为是正常的事情。

**在技能中的运作方式：**
- 通用模式："每次""总是"
- 失败模式："没有 Y 的 X = 失败"
- 建立规范

**使用时机：**
- 记录通用实践
- 警告常见失败
- 强化标准

**示例：**
```markdown
✅ 没有 todo 跟踪的清单 = 步骤被跳过。每次都是。
❌ 有些人觉得 todo 列表对清单很有帮助。
```

### 5. Unity（统一性）
**含义：** 共享身份、归属感、群体归属。

**在技能中的运作方式：**
- 协作性语言："我们的代码库""我们是同事"
- 共享目标："我们都想要质量"

**使用时机：**
- 协作工作流
- 建立团队文化
- 非层级实践

**示例：**
```markdown
✅ 我们是一起工作的同事。我需要你诚实的专业判断。
❌ 如果我说错了你应该可能告诉我。
```

### 6. Reciprocity（互惠）
**含义：** 回报所得利益的责任感。

**运作方式：**
- 谨慎使用 —— 可能会让人感觉是操纵
- 技能中很少需要

**避免时机：**
- 几乎总是（其他原则更有效）

### 7. Liking（好感）
**含义：** 对我们喜欢的人更愿意合作的偏好。

**运作方式：**
- **不要用于合规**
- 与诚实反馈文化相冲突
- 制造阿谀奉承

**避免时机：**
- 纪律执行时始终避免

## 按技能类型的原则组合

| 技能类型 | 使用 | 避免 |
|------------|-----|-------|
| 纪律执行类 | Authority + Commitment + Social Proof | Liking、Reciprocity |
| 指南/技术类 | 中等 Authority + Unity | 重 Authority |
| 协作类 | Unity + Commitment | Authority、Liking |
| 参考类 | 仅清晰性 | 所有说服原则 |

## 为什么这有效：心理学基础

**明确规则减少找借口：**
- "YOU MUST"消除决策疲劳
- 绝对性语言消除"这是例外吗？"的问题
- 明确的防借口驳回堵上特定漏洞

**实现意图创造自动化行为：**
- 清晰的触发器 + 必需的操作 = 自动执行
- "当 X，做 Y"比"通常做 Y"更有效
- 减少合规的认知负担

**LLM 是"类人类"的：**
- 在包含这些模式的人类文本上训练
- 权威性语言在训练数据中先于合规行为
- 承诺序列（声明 → 行动）被频繁建模
- 社会认同模式（每个人都做 X）建立规范

## 合乎伦理的使用

**正当使用：**
- 确保关键实践被遵循
- 创建有效的文档
- 防止可预测的失败

**不正当使用：**
- 为个人利益操纵
- 制造虚假紧迫感
- 基于内疚的合规

**检验标准：** 如果用户完全理解这个技术，它是否会服务于用户的真正利益？

## 研究引用

**Cialdini, R. B. (2021).** *Influence: The Psychology of Persuasion (New and Expanded).* Harper Business.
- 七大说服原则
- 影响力研究的实证基础

**Meincke, L., Shapiro, D., Duckworth, A. L., Mollick, E., Mollick, L., & Cialdini, R. (2025).** Call Me A Jerk: Persuading AI to Comply with Objectionable Requests. University of Pennsylvania.
- 在 N=28,000 次 LLM 对话中测试了 7 种原则
- 使用说服技术后合规率从 33% 提高到 72%
- Authority、commitment、scarcity 最为有效
- 验证了 LLM 行为的类人类模型

## 快速参考

设计技能时，问自己：

1. **它是什么类型？**（纪律 vs 指南 vs 参考）
2. **我想改变什么行为？**
3. **适用哪些原则？**（纪律类通常是 authority + commitment）
4. **我是否组合了太多？**（不要七种全部使用）
5. **这是否合乎伦理？**（是否服务于用户的真正利益？）
