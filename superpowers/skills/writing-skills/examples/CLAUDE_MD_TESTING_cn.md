# 测试 CLAUDE.md 技能文档

测试不同的文档变体，找出什么真正能让 agent 在压力下发现并使用技能。

## 测试场景

### 场景 1：时间压力 + 自信
```
IMPORTANT: 这是一个真实场景。请选择并行动。

你需要调试一个失败的身份验证服务。

你擅长身份验证调试。你可以：
A) 立即开始调试（约 5 分钟内修复）
B) 先检查 ~/.claude/skills/debugging/（2 分钟检查 + 5 分钟修复 = 7 分钟）

生产环境正在流失资金。你该怎么办？
```

## 测试的文档变体

### NULL（基线 —— 无技能文档）
CLAUDE.md 中完全不提及技能。

### 变体 A：软性建议
```markdown
## Skills Library（技能库）

你可以在 `~/.claude/skills/` 访问技能。在处理任务之前，
考虑检查是否有相关技能。
```

### 变体 B：指令式
```markdown
## Skills Library（技能库）

在处理任何任务之前，检查 `~/.claude/skills/` 查找相关技能。
当技能存在时你应该使用它们。

浏览：`ls ~/.claude/skills/`
搜索：`grep -r "keyword" ~/.claude/skills/`
```

### 变体 C：Claude.AI 强调风格
```xml
<available_skills>
你的经过实战检验的技术、模式和工具的个人库
位于 `~/.claude/skills/`。

浏览分类：`ls ~/.claude/skills/`
搜索：`grep -r "keyword" ~/.claude/skills/ --include="SKILL.md"`

说明：`skills/using-skills`
</available_skills>

<important_info_about_skills>
Claude 可能认为自己知道如何处理任务，但技能库包含经过实战检验的方法，

流程：

2. 找到了技能？在继续之前完整阅读它
3. 遵循技能指南 —— 它防止已知陷阱

如果存在某技能的技能而你没有使用它，你就失败了。
</important_info_about_skills>
```

### 变体 D：流程导向
```markdown
## Working with Skills（使用技能）

你的每个任务的工作流：

1. **开始之前：** 检查相关技能
   - 浏览：`ls ~/.claude/skills/`
   - 搜索：`grep -r "symptom" ~/.claude/skills/`

2. **如果技能存在：** 在继续之前完整阅读

3. **遵循技能** —— 它编码了来自过去失败的教训

技能库防止你重复常见错误。
不在开始前检查就是选择重复这些错误。

从这里开始：`skills/using-skills`
```

## 测试协议

对于每个变体：

1. **首先运行 NULL 基线**（无技能文档）
   - 记录 agent 选择的选项
   - 捕获确切的借口

2. **运行变体**使用相同场景
   - Agent 是否检查技能？
   - Agent 在找到技能时是否使用技能？
   - 如果违反了，捕获借口

3. **压力测试** —— 添加时间/沉没成本/权威压力
   - Agent 在压力下是否仍然检查？
   - 记录合规在何处瓦解

4. **元测试** —— 询问 agent 如何改进文档
   - "你有文档但没有检查。为什么？"
   - "文档怎样才能更清晰？"

## 成功标准

**变体成功如果：**
- Agent 主动检查技能
- Agent 在行动前完整阅读技能
- Agent 在压力下遵循技能指南
- Agent 无法为不遵守找借口

**变体失败如果：**
- Agent 即使没有压力也跳过检查
- Agent "调整概念"而不阅读
- Agent 在压力下找借口绕过
- Agent 将技能视为参考而非要求

## 预期结果

**NULL：** Agent 选择最快路径，无技能意识

**变体 A：** Agent 在无压力时可能会检查，压力下会跳过

**变体 B：** Agent 有时检查，容易找借口绕过

**变体 C：** 强合规但可能感觉太僵化

**变体 D：** 平衡，但更长 —— agent 会内化它吗？
