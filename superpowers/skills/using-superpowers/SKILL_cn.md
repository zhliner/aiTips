## 规则

**在任何回复或操作之前，调用相关或被请求的技能** —— 包括澄清性问题、探索代码库或检查文件。如果最终发现不适用，你可以不使用它。

**在进入计划模式之前：** 如果你还没有进行头脑风暴，请先调用 brainstorming 技能。

然后宣告"正在使用 [技能名称] 来 [目的]"，并严格遵循该技能。如果技能中包含清单，请为每一项创建一个 todo。

## 技能优先级

当多个技能同时适用时，流程类技能优先 —— 它们确定方法，然后实施类技能（如 frontend-design 等）将其执行。Brainstorming 和 systematic-debugging 是 Superpowers 中最常用的流程类技能，但这一规则适用于所有技能。

- "我们来构建 X" → 先执行 superpowers:brainstorming，然后是实施类技能。
- "修复这个 bug" → 先执行 superpowers:systematic-debugging，然后是领域技能。

## 危险信号

以下想法意味着**停止**——你正在找借口：

| 想法 | 现实 |
|---------|---------|
| "这只是一个简单的问题" | 问题就是任务。检查技能。 |
| "我需要更多上下文" | 技能检查在澄清性问题**之前**。 |
| "让我先探索代码库" | 技能告诉你**如何**探索。先检查技能。 |
| "我可以快速检查一下 git/文件" | 文件缺少对话上下文。检查技能。 |
| "让我先收集信息" | 技能告诉你**如何**收集信息。 |
| "这不需要正式技能" | 如果技能存在，就使用它。 |
| "我记得这个技能" | 技能会演进。读取当前版本。 |
| "这不算一个任务" | 操作 = 任务。检查技能。 |
| "这个技能小题大做了" | 简单的事情会变复杂。使用它。 |
| "我先做这一件事吧" | 在做**任何事**之前先检查。 |
| "这感觉很高效" | 无纪律的行动浪费时间。技能可以防止这一点。 |
| "我知道那是什么意思" | 知道概念 ≠ 使用技能。调用它。 |
