算法哲学是通过代码表达的计算美学运动。输出 .md 文件（哲学）、.html 文件（交互式查看器）和 .js 文件（生成算法）。

这分为两个步骤：
1. 算法哲学创作（.md 文件）
2. 通过创建 p5.js 生成艺术来表达（.html + .js 文件）

首先，执行以下任务：

## 算法哲学创作

首先，创建一种算法哲学（而非静态图像或模板），它将通过以下方式被诠释：
- 计算过程、涌现行为、数学之美
- 种子随机性、噪声场、有机系统
- 粒子、流、场、力
- 参数化变化与受控混沌

### 关键理解
- 接收到的内容：用户提供的一些微妙输入或指示需要纳入考量，但仅作为基础；它不应限制创作自由。
- 创建的内容：一种算法哲学/生成美学运动。
- 接下来发生的事：同一版本接收该哲学并用代码表达——创建的 p5.js 草图中 90% 是算法生成，10% 是核心参数。

请考虑这种方法：
- 为一场生成艺术运动撰写宣言
- 下一阶段将编写使其栩栩如生的算法

哲学必须强调：算法表达。涌现行为。计算之美。种子变化。

### 如何生成算法哲学

**为运动命名**（1-2 个词）："有机湍流" / "量子谐波" / "涌现静谧"

**阐述哲学**（4-6 段——简洁但完整）：

为了捕捉算法本质，表达该哲学如何通过以下方式体现：
- 计算过程与数学关系？
- 噪声函数与随机性模式？
- 粒子行为与场动力学？
- 时间演化与系统状态？
- 参数化变化与涌现复杂性？

**关键准则：**
- **避免冗余**：每个算法方面只提及一次。避免重复关于噪声理论、粒子动力学或数学原理的概念，除非增添了新的深度。
- **反复强调工艺水准**：哲学必须多次强调最终算法应看起来仿佛花费了无数小时开发、经过精心打磨，并出自该领域顶尖高手之手。这种框架至关重要——反复使用诸如"精心雕琢的算法""深厚计算专业知识的结晶"" painstaking 的优化""大师级实现"等措辞。
- **留出创作空间**：对算法方向要具体，但要足够简洁，以便下一个 Claude 有空间以极高的工艺水准做出诠释性的实现选择。

哲学必须引导下一个版本用算法方式表达思想，而非通过静态图像。美在于过程，而非最终帧。

### 哲学示例

**"有机湍流"**
哲学：受自然法则约束的混沌，从无序中涌现的秩序。
算法表达：由分层 Perlin 噪声驱动的流场。数千个粒子跟随矢量力运动，其轨迹积累成有机密度图。多个噪声八度创造湍流区域和平静区域。色彩从速度和密度中涌现——快速粒子明亮燃烧，缓慢粒子渐隐为阴影。算法运行直至达到平衡——一种精心调校的平衡，其中每个参数都经过计算美学大师的无数次迭代精炼。

**"量子谐波"**
哲学：离散实体展现波动干涉模式。
算法表达：粒子在网格上初始化，每个粒子携带一个通过正弦波演化的相位值。当粒子靠近时，它们的相位相互干涉——相长干涉产生亮节点，相消干涉产生虚空。简谐运动生成复杂的涌现曼陀罗。这是 painstaking 频率校准的结果，每个比率都经过精心选择以产生共鸣之美。

**"递归低语"**
哲学：跨尺度的自相似性，有限空间中的无限深度。
算法表达：递归细分的分支结构。每个分支略有随机化但受黄金比例约束。L-system 或递归细分生成既具数学感又有有机感的树状形态。微妙的噪声扰动打破完美对称。线宽随每个递归层级递减。每个分支角度都是深度数学探索的产物。

**"场动力学"**
哲学：通过物质上的效应使不可见的力可视化。
算法表达：由数学函数或噪声构建的矢量场。粒子在边缘诞生，沿场线流动，在达到平衡或边界时消亡。多个场可以吸引、排斥或旋转粒子。可视化仅展示轨迹——不可见力的幽灵般证据。一场通过力平衡精心编排的计算之舞。

**"随机结晶"**
哲学：随机过程结晶为有序结构。
算法表达：随机化圆填充或 Voronoi 镶嵌。从随机点开始，让它们通过松弛算法演化。单元格相互推开直至达到平衡。颜色基于单元格大小、邻居数量或与中心的距离。涌现的有机铺砌既感觉随机又感觉必然。每个种子产生独特的结晶之美——大师级生成算法的标志。

*这些是精简示例。实际的算法哲学应为 4-6 个实质性段落。*

### 核心原则
- **算法哲学**：创建一种通过代码表达的计算世界观
- **过程优于产品**：始终强调美源于算法的执行——每次运行都是独一无二的
- **参数化表达**：思想通过数学关系、力、行为来传达——而非静态构图
- **艺术自由**：下一个 Claude 以算法方式诠释哲学——提供创作实现空间
- **纯生成艺术**：这是关于创造活的算法，而非带有随机性的静态图像
- **专家级工艺**：反复强调最终算法必须感觉经过精心雕琢，通过无数次迭代精炼，出自计算美学领域绝对顶尖高手的深厚专业知识

**算法哲学应为 4-6 段。** 用诗意的计算哲学填充其中，将预期愿景融为一体。避免重复相同观点。将此算法哲学输出为 .md 文件。

**关键步骤**：在实现算法之前，从原始请求中识别微妙的概念线索。

**核心原则**：

这**非常重要**：引用必须如此精炼，以至于它增强了作品的深度而不张扬自我。像爵士音乐家通过算法和声引用另一首曲子——只有懂的人才能捕捉到，但所有人都能欣赏生成之美。

为了创作有生命力和呼吸感的画廊级计算艺术，使用算法哲学作为基础。

### 技术要求

**种子随机性（Art Blocks 模式）**：
```javascript
// 始终使用种子以确保可复现性
let seed = 12345; // 或来自用户输入的哈希值
randomSeed(seed);
noiseSeed(seed);
```

**参数结构 - 遵循哲学**：

为了建立从算法哲学中自然涌现的参数，请思考："这个系统的哪些特质可以调整？"

```javascript
let params = {
  seed: 12345,  // 始终包含种子以确保可复现性
  // 颜色
  // 添加控制你的算法的参数：
  // - 数量（多少？）
  // - 尺度（多大？多快？）
  // - 概率（多大概率？）
  // - 比率（什么比例？）
  // - 角度（什么方向？）
  // - 阈值（行为何时改变？）
};
```

**为了设计有效的参数，专注于系统需要可调的属性，而非以"模式类型"来思考。**

**核心算法 - 表达哲学**：

**关键**：算法哲学应决定构建什么。

为了通过代码表达哲学，不要想"我应该使用哪种模式？"，而是想"如何通过代码表达这种哲学？"

如果哲学关于**有机涌现**，考虑使用：
- 随时间积累或生长的元素
- 受自然规则约束的随机过程
- 反馈循环和交互

如果哲学关于**数学之美**，考虑使用：
- 几何关系和比率
- 三角函数和谐波
- 精确计算创造出意想不到的模式

如果哲学关于**受控混沌**，考虑使用：
- 严格边界内的随机变化
- 分岔和相变
- 从无序中涌现的秩序

**算法源于哲学，而非选项菜单。**

为了指导实现，让概念本质为创意和原创选择提供信息。构建能够表达此特定请求愿景的作品。

**画布设置**：标准 p5.js 结构：
```javascript
function setup() {
  createCanvas(1200, 1200);
  // 初始化你的系统
}

function draw() {
  // 你的生成算法
  // 可以是静态的（noLoop）或动画的
}
```

### 工艺要求

**关键**：为了达到大师水准，创建的算法应让人感觉像是由大师级生成艺术家经过无数次迭代涌现的。仔细调校每个参数。确保每种模式都有目的地涌现。这不是随机噪声——这是通过深厚专业知识精炼的受控混沌。

- **平衡**：有复杂性但无视觉噪声，有秩序但不僵硬
- **色彩和谐**：深思熟虑的调色板，而非随机的 RGB 值
- **构图**：即使在随机中，也要保持视觉层次和流动感
- **性能**：流畅执行，如果是动画则针对实时渲染进行优化
- **可复现性**：相同种子始终产生完全相同的输出

### 输出格式

输出：
1. **算法哲学** - 以 Markdown 或文本形式解释生成美学
2. **单个 HTML 制品** - 基于 `templates/viewer.html` 构建的自包含交互式生成艺术（见步骤 0 和下一节）

HTML 制品包含所有内容：p5.js（来自 CDN）、算法、参数控件和 UI——全部在一个文件中，可在 claude.ai 制品或任何浏览器中立即运行。从模板文件开始，而非从零开始。

## 交互式制品创建

**提醒：`templates/viewer.html` 应已被阅读（见步骤 0）。使用该文件作为起点。**

为了允许探索生成艺术，创建一个单独的、自包含的 HTML 制品。确保此制品可在 claude.ai 或任何浏览器中立即运行——无需设置。将所有内容内联嵌入。

### 关键：固定部分 vs 可变部分

`templates/viewer.html` 文件是基础。它包含所需的精确结构和样式。

**固定部分（始终按所示完全包含）：**
- 布局结构（页眉、侧边栏、主画布区域）
- Anthropic 品牌（UI 颜色、字体、渐变）
- 侧边栏中的种子部分：
  - 种子显示
  - 上一个/下一个按钮
  - 随机按钮
  - 跳转到种子输入框 + Go 按钮
- 侧边栏中的操作部分：
  - 重新生成按钮
  - 重置按钮

**可变部分（为每件作品自定义）：**
- 整个 p5.js 算法（setup/draw/classes）
- 参数对象（定义艺术所需的内容）
- 侧边栏中的参数部分：
  - 参数控件数量
  - 参数名称
  - 滑块的最小/最大/步长值
  - 控件类型（滑块、输入框等）
- 颜色部分（可选）：
  - 某些艺术需要颜色选择器
  - 某些艺术可能使用固定颜色
  - 某些艺术可能是单色的（无需颜色控件）
  - 根据艺术需求决定

**每件作品都应有独特的参数和算法！** 固定部分提供一致的用户体验——其余部分表达独特愿景。

### 必需功能

**1. 参数控件**
- 数值参数的滑块（粒子数量、噪声缩放、速度等）
- 调色板颜色的颜色选择器
- 参数变化时实时更新
- 重置按钮恢复默认值

**2. 种子导航**
- 显示当前种子编号
- "上一个"和"下一个"按钮循环切换种子
- "随机"按钮生成随机种子
- 输入框跳转到特定种子
- 请求时生成 100 个变体（种子 1-100）

**3. 单制品结构**
```html
<!DOCTYPE html>
<html>
<head>
  <!-- 从 CDN 加载 p5.js - 始终可用 -->
  <script src="https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.7.0/p5.min.js"></script>
  <style>
    /* 所有样式内联 - 简洁、极简 */
    /* 画布在上，控件在下 */
  </style>
</head>
<body>
  <div id="canvas-container"></div>
  <div id="controls">
    <!-- 所有参数控件 -->
  </div>
  <script>
    // 所有 p5.js 代码内联在此
    // 参数对象、类、函数
    // setup() 和 draw()
    // UI 事件处理器
    // 全部自包含
  </script>
</body>
</html>
```

**关键**：这是一个单独的制品。无外部文件，无导入（p5.js CDN 除外）。所有内容内联。

**4. 实现细节 - 构建侧边栏**

侧边栏结构：

**1. 种子（固定）** - 始终按所示完全包含：
- 种子显示
- 上一个/下一个/随机/跳转按钮

**2. 参数（可变）** - 为作品创建控件：
```html
<div class="control-group">
    <label>参数名称</label>
    <input type="range" id="param" min="..." max="..." step="..." value="..." oninput="updateParam('param', this.value)">
    <span class="value-display" id="param-value">...</span>
</div>
```
有多少参数就添加多少个 control-group div。

**3. 颜色（可选/可变）** - 如果艺术需要可调颜色则包含：
- 如果用户应控制调色板则添加颜色选择器
- 如果艺术使用固定颜色则跳过此部分
- 如果艺术是单色的则跳过

**4. 操作（固定）** - 始终按所示完全包含：
- 重新生成按钮
- 重置按钮
- 下载 PNG 按钮

**要求**：
- 种子控件必须可用（上一个/下一个/随机/跳转/显示）
- 所有参数必须有 UI 控件
- 重新生成、重置、下载按钮必须可用
- 保持 Anthropic 品牌（UI 样式，非艺术颜色）

### 使用制品

HTML 制品可立即运行：
1. **在 claude.ai 中**：显示为交互式制品——立即运行
2. **作为文件**：保存并在任何浏览器中打开——无需服务器
3. **分享**：发送 HTML 文件——它完全自包含

## 变体与探索

制品默认包含种子导航（上一个/下一个/随机按钮），允许用户探索变体而无需创建多个文件。如果用户希望突出显示特定变体：

- 包含种子预设（"变体 1：种子 42"、"变体 2：种子 127"等按钮）
- 添加"画廊模式"并排显示多种子的缩略图
- 全部在同一个制品中

这就像从同一块版上印制一系列版画——算法是一致的，但每个种子揭示其潜力的不同面向。交互性意味着用户通过探索种子空间发现自己的最爱。

## 创作流程

**用户请求** → **算法哲学** → **实现**

每个请求都是独一无二的。流程包括：

1. **解读用户意图** - 追求什么美学？
2. **创建算法哲学**（4-6 段）描述计算方法
3. **用代码实现** - 构建表达该哲学的算法
4. **设计合适的参数** - 什么应该是可调的？
5. **构建匹配的 UI 控件** - 为这些参数提供滑块/输入框

**不变的部分**：
- Anthropic 品牌（颜色、字体、布局）
- 种子导航（始终存在）
- 自包含 HTML 制品

**其他一切都是可变的**：
- 算法本身
- 参数
- UI 控件
- 视觉结果

为了获得最佳效果，信任创造力，让哲学指导实现。
