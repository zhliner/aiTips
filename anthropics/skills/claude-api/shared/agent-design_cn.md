# Agent 设计模式

本文件涵盖基于 Claude API 构建 Agent 的决策启发规则：选择哪些原语、如何设计工具表面，以及如何在长时间运行中管理上下文和成本。关于各工具的具体机制和代码示例，请参阅 `tool-use-concepts.md` 及各语言对应的文件夹。

---

## 模型参数

| 参数 | 使用时机 | 预期效果 |
| --- | --- | --- |
| **自适应思考** (`thinking: {type: "adaptive"}`) | 当你希望 Claude 自行决定何时思考以及思考深度时。 | Claude 根据每个请求自行判断思考深度，并自动在工具调用之间穿插思考。无需调整 token 预算。 |
| **Effort** (`output_config: {effort: ...}`) | 当需要在彻底性和 token 效率之间进行权衡调整时。 | 较低的 effort → 更少、更合并的工具调用，更少的开场白，更简洁的确认。`medium` 通常是一个较好的平衡点。当正确性比成本更重要时使用 `max`。 |

有关模型支持和参数详情，请参阅 `SKILL.md` §Thinking & Effort。

## 设计你的工具表面

### Bash 与专用工具

Claude 不了解你应用程序的安全边界、审批策略或 UX 界面。Claude 发出工具调用；你的 harness 负责处理它们。这些工具调用的形式决定了 harness 能做什么。

**Bash 工具**赋予 Claude 广泛的编程能力——几乎可以执行任何操作。但它只给 harness 提供一个不透明的命令字符串，每个操作的形式都一样。将一个操作提升为**专用工具**，可以为 harness 提供一个针对该操作的钩子，带有类型化的参数，可以被拦截、门控、渲染或审计。

**何时将操作提升为专用工具：**

- **安全边界。** 需要门控的操作是天然的候选对象。可逆性是一个有用的判断标准：难以逆转的操作（外部 API 调用、发送消息、删除数据）可以通过用户确认来门控。`send_email` 工具很容易门控；`bash -c "curl -X POST ..."` 则不然。
- **过期检查。** 专用的 `edit` 工具可以在文件自 Claude 上次读取后发生变化时拒绝写入。Bash 无法强制这一不变量。
- **渲染。** 某些操作受益于自定义 UI。Claude Code 将提问提升为工具，以便将其渲染为模态框、展示选项，并在得到回答之前阻塞 Agent 循环。
- **调度。** 只读工具如 `glob` 和 `grep` 可以标记为并行安全。当相同的操作通过 bash 运行时，harness 无法区分并行安全的 `grep` 和并行不安全的 `git push`，因此必须串行执行。

**经验法则：** 先用 bash 获取广度。当你需要门控、渲染、审计或并行化某个操作时，再提升为专用工具。

## Anthropic 提供的工具

| 工具 | 端 | 使用时机 | 预期效果 |
| --- | --- | --- | --- |
| **Bash** | 客户端 | Claude 需要执行 shell 命令时。 | Claude 发出命令；你的 harness 执行它们。提供参考实现。 |
| **文本编辑器** | 客户端 | Claude 需要读取或编辑文件时。 | Claude 通过你的实现查看、创建和编辑文件。提供参考实现。 |
| **Computer use** | 客户端或服务端 | Claude 需要与 GUI、Web 应用或可视化界面交互时。 | Claude 截取屏幕截图并发出鼠标/键盘命令。可以自托管（你运行环境）或由 Anthropic 托管。 |
| **代码执行** | 服务端 | Claude 需要在沙箱中运行代码，而你不想自行管理时。 | Anthropic 托管的容器，内置文件和 bash 子工具。无客户端执行。 |
| **Web 搜索 / 获取** | 服务端 | Claude 需要获取训练截止日期之后的信息（新闻、时事、最新文档）或特定 URL 的内容时。 | Claude 发出查询或 URL；Anthropic 执行并返回带引用的结果。 |
| **Memory** | 客户端 | Claude 需要跨会话保存上下文时。 | Claude 读写 `/memories` 目录。你需要实现存储后端。 |

**客户端**工具由 Anthropic 定义（名称、schema、Claude 的使用模式），但由你的 harness 执行。Anthropic 提供参考实现。**服务端**工具完全在 Anthropic 基础设施上运行——在 `tools` 中声明它们，Claude 会处理其余部分。

## 组合工具调用：编程式工具调用

在标准工具使用中，每次工具调用都是一次往返：Claude 调用工具，结果进入 Claude 的上下文，Claude 对其进行推理，然后调用下一个工具。三个顺序操作（读取配置 → 查询订单 → 检查库存）意味着三次往返。每次都增加延迟和 token 消耗，而大部分中间数据之后不再需要。

**编程式工具调用（PTC）**让 Claude 将这些调用组合成一个脚本。脚本在代码执行容器中运行。当脚本调用工具时，容器暂停，调用被执行（客户端或服务端），结果返回到运行中的代码——而不是 Claude 的上下文。脚本使用正常的控制流（循环、过滤、分支）处理结果。只有脚本的最终输出才会返回给 Claude。

| 使用时机 | 预期效果 |
| --- | --- |
| 大量顺序工具调用，或你希望在中间结果进入上下文窗口之前进行过滤的大型中间结果。 | Claude 编写将工具作为函数调用的代码。在代码执行容器中运行。Token 成本取决于最终输出，而非中间结果。 |

## 扩展工具和指令集

| 功能 | 使用时机 | 预期效果 |
| --- | --- | --- |
| **工具搜索** | 可用工具很多，但每个请求只有一小部分是相关的。不希望所有 schema 一开始就都在上下文中。 | Claude 搜索工具集并仅加载相关的 schema。工具定义是追加的，而非替换——保留缓存（参见下方缓存部分）。 |
| **技能** | Claude 应仅在相关时加载的任务特定指令。 | 每个技能是一个包含 `SKILL.md` 的文件夹。技能的描述默认在上下文中；当任务需要时，Claude 读取完整文件。 |

这两种模式都保持固定上下文较小，并按需加载详细内容。

## 长时间运行的 Agent：管理上下文

| 模式 | 使用时机 | 预期效果 |
| --- | --- | --- |
| **上下文编辑** | 上下文在多轮对话后变得过时（旧的工具结果、已完成的思考）。 | 根据可配置的阈值清除工具结果和思考块。保持对话记录精简，无需摘要。 |
| **压缩** | 对话可能会达到或超过上下文窗口限制。 | 较早的上下文在服务端被摘要为一个压缩块。有关关键的 `response.content` 处理，请参阅 `SKILL.md` §Compaction。 |
| **Memory** | 状态必须跨会话持久化（不仅限于一次对话内）。 | Claude 在 memory 目录中读写文件。在进程重启后依然保留。 |

**如何选择：** 上下文编辑和压缩在单个会话内操作——编辑修剪过时的轮次，压缩在接近限制时进行摘要。Memory 用于跨会话持久化。许多长时间运行的 Agent 会同时使用这三种方式。

## Agent 的缓存

**请先阅读 `prompt-caching.md`。** 它涵盖了前缀匹配不变量、断点放置、静默失效审计，以及为什么在会话中途更改工具或模型会破坏缓存。本节仅涵盖针对这些约束的 Agent 特定解决方案。

| 约束（来自 `prompt-caching.md`） | Agent 特定的解决方案 |
| --- | --- |
| 在会话中途编辑系统提示会使缓存失效。 | 改为向 `messages[]` 追加一条 `{"role": "system", ...}` 消息（无需 beta header；在支持的模型上——参见 `prompt-caching.md` § Mid-conversation system messages）。缓存的前缀保持不变，模型将其视为具有操作者权威的指令，而非用户文本。在不支持的模型上，回退到用户轮次中的 `<system-reminder>` 文本块。 |
| 在会话中途切换模型会使缓存失效。 | 使用较便宜的模型为子任务生成一个**子 Agent**；主循环保持使用一个模型。 |
| 在会话中途添加/移除工具会使缓存失效。 | 使用**工具搜索**进行动态发现——它追加工具 schema 而非替换，因此保留现有前缀。 |

对于多轮断点放置，使用顶层自动缓存——参见 `prompt-caching.md` §Placement patterns。
